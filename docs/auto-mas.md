# AUTO-MAS read-only status

The Windows collector can optionally read AUTO-MAS on the **same PC**. It requests `GET http://127.0.0.1:36163/api/core/health` and, when supported, `GET http://127.0.0.1:36163/api/dispatch/runtime-snapshot` every sampling cycle. The newer snapshot endpoint is in [AUTO-MAS source](https://github.com/AUTO-MAS-Project/AUTO-MAS/blob/main/app/api/dispatch.py). The default production HTTP port is defined in [main.py](https://github.com/AUTO-MAS-Project/AUTO-MAS/blob/main/main.py). The port can be overridden by AUTO-MAS; if you use another local port, create `auto-mas-port.txt` beside `Collect.ps1` containing only that port number.

The collector uploads only backend availability, version, latest historical result time/outcome, and, when the snapshot API exists, active task count, scheduled script count, and up to eight task summaries with at most six script names and status strings each. Script names are therefore visible to the dashboard owner. It does **not** upload the runtime snapshot's raw logs, user IDs, user names, queue IDs or full configuration files. No AUTO-MAS commands are sent. The receiver rejects unexpected fields.

**AUTO-MAS v5.4.0 has the health endpoint but no runtime snapshot endpoint.** For this version, the collector also calls the read-only-by-behavior `POST /api/history/search` at most once every five minutes and uploads only the newest record's timestamp and `DONE`/`ERROR` status. The dashboard labels this **History only**; it cannot infer whether a task is running now. Later versions with the snapshot endpoint can show live task/script states. A historical `DONE` does not prove current progress. The hardware monitor works even when AUTO-MAS is stopped. There is no independent task watchdog or alert in this version.

Keep the AUTO-MAS backend port local to the Windows PC. Do not add a public firewall or router rule for port 36163. The collector does not need a new inbound port: only its existing outbound HTTPS upload is used.

After updating both server and collector, run `Collect.ps1 -Once -NoUpload` locally to inspect a single sample. Look for `autoMas.state`. `ready` means the runtime snapshot was read; `limited` means the backend responded but a live task snapshot is unavailable, as on v5.4.0; `unavailable` can mean AUTO-MAS is stopped, a different port is configured, or the request timed out. Because the sample may include script names, keep diagnostic output private.
